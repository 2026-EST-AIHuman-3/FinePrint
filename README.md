# FinePrint
### 구독형 서비스 약관 기반 소비자 보호 AI Agent

## 1. 프로젝트 소개

FinePrint는 구독 서비스의 해지·환불·자동결제 문제에 대해  
서비스 약관과 소비자 보호 자료를 함께 검색하고, 답변을 검증해  
사용자가 확인해야 할 사항과 다음 행동을 안내하는 AI Agent입니다.

> **개발 기간**: 2026.07.01 ~ 2026.07.23

---
## 2. 기획 배경

- 구독 서비스 이용 과정에서 해지·환불·자동결제 관련 문제가 반복적으로 발생
- 해지 수수료와 취소 조건이 약관과 절차 속에 포함되어 있어 사용자가 직접 확인하기 어려움
- 같은 문제라도 결제 시점, 해지 완료 여부, 서비스 이용 여부에 따라 확인해야 할 조건이 달라짐
- 일반 생성형 AI의 답변은 실제 약관과 일치하는지 확인하기 어려움

> **FinePrint는 사용자의 문제 상황을 서비스 약관 및 소비자 보호 근거와 연결하고,  
> 확인사항과 다음 행동을 안내하기 위해 기획했습니다.**

## 3. 주요 기능

#### 1) 약관 수집 및 문서 업로드
- 공식 약관 URL을 탐색하고 웹페이지 본문을 수집
- 자동 수집이 어려운 경우 URL 또는 PDF·TXT 파일 입력 지원
- 약관과 법령의 구조를 반영해 조항·섹션 단위로 분할

#### 2) Hybrid RAG 기반 근거 검색
- 서비스 이용약관과 소비자 보호 자료를 함께 검색
- 의미 기반 검색과 도메인 키워드 재정렬을 결합
- 서비스명과 문서 유형 메타데이터를 활용해 관련 없는 문서 제외

#### 3) 근거 검증 AI Agent
- 사용자 질문을 해지·환불·자동결제·결제·개인정보 등의 유형으로 분류
- 생성된 답변과 검색 근거의 일치 여부를 별도로 검증
- 실패 원인에 따라 답변 재생성 또는 근거 재검색 수행
- 반복 검증 후에도 근거가 부족하면 무리하게 단정하지 않고 근거 부족 안내 제공

#### 4) 실행 가능한 답변 제공
- 문제 상황에 대한 조건부 결론 제공
- 해지일·결제일·서비스 이용 여부 등 확인사항 안내
- 고객센터 문의 방법과 준비 자료 제시
- 실제 사용한 조항과 원문, 출처 링크 제공

## 7. 답변 검증 및 재시도 구조

FinePrint는 검색된 문서를 바탕으로 답변을 생성한 뒤,  
별도의 검증 단계에서 답변이 실제 근거와 일치하는지 확인합니다.

검증에 실패한 경우 모든 답변을 같은 방식으로 다시 처리하지 않고,  
실패 원인에 따라 재시도 경로를 구분했습니다.

| 분기 경로 | 판단 기준 | 처리 방식 |
|---|---|---|
| `PASS` | 답변이 검색된 근거와 일치함 | 최종 답변 생성 |
| `REGENERATE` | 근거는 충분하지만 답변 표현이 부정확하거나 과도하게 단정적임 | 기존 근거를 유지하고 답변만 재생성 |
| `RETRIEVE_AGAIN` | 사용자의 상황을 판단하기 위한 근거가 부족함 | 검색 전략을 보완해 관련 문서를 다시 검색 |
| `INSUFFICIENT` | 설정된 최대 재시도 횟수에 도달한 후에도 필요한 근거를 확보하지 못함 | 가능 여부를 단정하지 않고 근거 부족 안내 제공 |

### 재시도 제한

- 검증 실패 시 `retry_count`를 증가시킵니다.
- 최대 재시도 횟수를 설정해 무한 반복을 방지했습니다.
- 재시도 이후에도 근거가 부족한 경우, 확인사항과 추가로 필요한 자료를 안내합니다.

> 답변 생성 실패와 검색 실패를 구분해 필요한 단계만 다시 수행함으로써,  
> 불필요한 반복을 줄이고 근거와 답변의 일치도를 높였습니다.

## 9. 데이터 구성과 Hybrid RAG

### 데이터 구성

FinePrint는 서비스가 정한 계약 조건과 소비자 보호 기준을 함께 확인하기 위해  
두 종류의 문서를 지식베이스로 구축했습니다.

| 데이터 유형 | 구성 |
|---|---|
| 서비스 문서 | 이용약관, 개인정보처리방침, 환불 정책, FAQ |
| 소비자 보호 자료 | 관련 법률, 공정위·소비자원 지침, 개인정보 보호 기준 |

- 서비스 문서: **29개**
- 관련 법률: **9개**
- 소비자 보호 및 개인정보 지침: **21개**
- 분류·전처리를 완료해 핵심 지식베이스로 활용한 문서: **총 59개**

### 문서 전처리

약관과 법령의 조항 구조가 검색 과정에서 유지되도록 문서 유형별 분할 기준을 적용했습니다.

- 한국어 약관·법령: `제1조`, `제2조`와 같은 조문 단위
- 영문 약관: `2.6`, `2.7`과 같은 숫자 섹션 단위
- 소비자 보호 지침: 번호 또는 소제목 단위
- 구조를 인식하기 어려운 문서: 1,000자 단위, 120자 중첩 방식으로 보완
- 각 청크에 서비스명, 문서 유형, 조항 번호, 출처 등의 메타데이터 저장

### Hybrid RAG 검색 방식

FinePrint는 단순한 의미 유사도 검색만 사용하지 않고,  
임베딩 검색과 도메인 키워드 재정렬을 결합했습니다.

1. 사용자 질문과 의미가 유사한 문서 후보 검색
2. 해지·환불·자동결제·개인정보 등의 도메인 키워드로 후보 재정렬
3. 서비스명과 문서 유형 메타데이터 필터 적용
4. 서비스 약관과 소비자 보호 자료를 각각 검색해 Agent에 전달

이를 통해 다른 서비스의 약관이나 관련성이 낮은 조항이  
답변 근거에 포함되는 가능성을 줄였습니다.

## 10. 문제 분석 및 품질 개선

초기 Agent 테스트에서는 검색된 근거에 없는 내용을 포함하거나,
환불 가능 여부를 과도하게 단정하는 답변이 생성되는 문제가 있었습니다.

### 초기 문제

- 검색 문서에 직접적인 환불 조항이 없는데도 전액 환불이 가능하다고 단정
- 해지 완료 시점과 결제 시점 등 판단에 필요한 정보가 부족한 상태에서 결론 생성
- 검증에 실패한 모든 경우를 같은 방식으로 다시 처리
- 재시도 종료 조건이 없을 경우 반복 실행될 가능성 존재

### 개선 내용

1. **답변과 근거의 일치 여부 검증**
   - 생성된 답변의 각 판단이 검색된 약관과 소비자 보호 자료에 근거하는지 확인
   - 근거보다 강한 표현이나 문서에 없는 내용을 포함하면 검증 실패 처리

2. **실패 원인에 따른 재시도 경로 분리**
   - 근거는 충분하지만 답변 표현이 부정확한 경우 `REGENERATE`
   - 판단에 필요한 근거가 부족한 경우 `RETRIEVE_AGAIN`

3. **근거 부족 답변 제공**
   - 재시도 후에도 근거가 부족하면 환불 가능 여부를 억지로 단정하지 않음
   - 추가 확인사항, 필요 자료 및 고객센터 문의 방향을 안내

4. **최대 재시도 횟수 설정**
   - `retry_count`를 상태로 관리
   - 최대 재시도 횟수를 제한해 무한 루프 방지

> 단순히 답변을 다시 생성하는 방식이 아니라,
> 실패 원인을 분석하고 필요한 단계만 다시 수행하도록 Agent 흐름을 개선했습니다.

## 11. 테스트 및 평가 결과

FinePrint의 주요 검증 경로가 의도한 대로 동작하는지 확인하기 위해  
환불, 자동결제·갱신, 개인정보 시나리오를 대상으로 테스트했습니다.

![FinePrint 테스트 결과](./images/test-results.png)

- **환불**: 검색 1회, 생성 1회, 검증 1회로 첫 검증에서 `PASS`
- **자동결제·갱신**: 검색 근거는 유지하고 답변을 재생성해 `REGENERATE` 후 `PASS`
- **개인정보**: 초기 근거가 부족해 재검색을 수행하고 `RETRIEVE_AGAIN` 후 `PASS`

> 본 평가는 대규모 정량 평가가 아니라,  
> 검증 실패 원인에 따라 재생성 또는 재검색 경로가 정상적으로 동작하는지 확인한 시나리오 기반 테스트입니다.

## 12. 실행 방법

### 1) 환경 설정

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install -r requirements.txt
python -m playwright install chromium

Copy-Item .env.example .env
```

프로젝트 루트의 `.env` 파일에 API 키를 설정합니다.

```env
OPENAI_API_KEY=your_openai_api_key
TAVILY_API_KEY=your_tavily_api_key
```

> `OPENAI_API_KEY`: Agent 답변 생성 및 검증에 필요  
> `TAVILY_API_KEY`: 등록되지 않은 서비스의 공식 약관 URL 자동 탐색 시 필요

### 2) FastAPI 서버 실행

```powershell
uvicorn api:app --host 0.0.0.0 --port 8000 --reload
```

- Python API 기본 주소: [http://127.0.0.1:8000](http://127.0.0.1:8000)

### 3) React UI 실행

새 터미널에서 다음 명령을 실행합니다.

```powershell
Set-Location frontend
Copy-Item .env.example .env

npm install
npm run dev
```

- React UI 기본 접속 주소: [http://localhost:3000](http://localhost:3000)

> Python API를 먼저 실행한 뒤 React UI를 실행해야 합니다.

### 4) 서비스 이용 흐름

1. 서비스명 입력
2. 기존 지식 DB에서 해당 서비스 문서 확인
3. 문서가 없으면 공식 URL 자동 탐색 및 수집
4. 자동 수집이 어려운 경우 URL 또는 PDF·TXT 직접 입력
5. 문제 상황 입력
6. Hybrid RAG 검색 및 검증 Agent 실행
7. 근거, 확인사항, 다음 행동 확인

#### 주요 API

| Method | Endpoint | 기능 |
|---|---|---|
| `POST` | `/services/prepare` | DB 확인 후 서비스 문서 자동 수집 및 인제스트 |
| `POST` | `/services/url` | 사용자가 입력한 공식 URL 수집 및 인제스트 |
| `POST` | `/services/document` | PDF·TXT 문서 업로드 및 인제스트 |
| `POST` | `/questions` | Hybrid RAG 검색과 검증 Agent 실행 |
